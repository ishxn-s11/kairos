# Kairos — Next.js Frontend

The primary interface for the open-source Kairos financial decision engine,
built with **React 18 / Next.js 16 (App Router)**. It includes persistent light
and dark themes, a live decision test bench, and account activity connected to
the Flask API. The frontend exports to static files; live decisions and accounts
require the backend. See the [project README](../README.md) for full setup.

## Routes

| Route | Content |
|---|---|
| `/` | Product homepage with animated financial charms, workflow cards, product principles, account navigation, and theme controls |
| `/about/` | Editorial product story covering the premise, four-step engine, deterministic safety model, operating principles, and proof points. |
| `/account/` | Login/register plus a private activity ledger. Accounts use the Flask backend, hashed passwords, expiring bearer sessions, and authenticated decision tracking. |
| `/results/` | Run statistics, status/method bars, **live decision explorer** (real `output.csv`), evidence gallery, 22-point validation, artifacts |
| `/workflow/` | Animated pipeline schematic with guided tour + free-run modes |
| `/test/` | Test bench: run requests from `/baseline.json` (real engine output), diff against `output.csv`, custom test cases, and a **live engine panel** that runs modified requests (new amount / date / partial flag) through the real Python pipeline via `code/serve_api.py` |
| `/work/stage-01/` … `/work/stage-07/` | Per-stage case studies with carousels and manifest-driven images |

## Run

```bash
npm ci
npm run dev            # http://localhost:8480

npm run build          # static export into out/
python -m http.server 8480 --bind 127.0.0.1 --directory out
```

Notes:

- Builds use `output: "export"` + `trailingSlash: true`: every route is an
  `index.html` inside a folder, so static servers work without redirects.
  Vercel publishes the same `out/` files and routes `/api/*` to Flask.
- The two frontends share selected styles, artwork, data files, and logic.
  **After editing a shared file, mirror the change and run
  `python code/tools/check_parity.py` from the repository root.** It exits
  non-zero on drift in the shared material. Page layouts and account/theme
  controls differ between the frontends. See `../code/README.md` for the checks.
- Internal hrefs therefore end in `/` (e.g. `/work/stage-01/`).
- `output.csv` is copied from the repo root into `public/` so the decision
  explorer fetches the real run data; `baseline.json` and the brand assets
  (favicon/icon set, `og-image.png`) live there too.
- Live requests on `/test/` need the engine endpoint: `python3 code/serve_api.py`
  (`http://127.0.0.1:8000`). The panel probes `/api/health`, stays inert when it
  is absent, and can be pointed elsewhere with `NEXT_PUBLIC_KAIROS_API=…`.
- Both the explorer and the test bench reflect their state in the URL, so views
  are shareable and restored on load — explorer
  `?status=&method=&q=&d=request_XX`, test bench `?id=&cmp=0&cases=…`, live runs
  `?lv=1&id=&amt=&date=&partial=0`.
- The light/dark theme toggle is available in both desktop and mobile navigation and persists in `localStorage`. If no preference has been saved, it follows the operating-system theme.
- Account data is stored locally in `.kairos/accounts.sqlite3` by default. Override it with `KAIROS_AUTH_DB`; set `KAIROS_API_CORS` to a restricted origin outside local development.
- Vercel deployments use same-origin `/api` routes and PostgreSQL account storage.
  The `?api=` debugging override is accepted only on local development hosts.
- Branding and social previews are set in `app/layout.jsx`. The base URL follows
  `NEXT_PUBLIC_SITE_URL`, Vercel's production hostname, or the local dev URL.

## Architecture

- `lib/data.js`, `lib/evidence.js` — ES-module copies of the static site's
  content data (stages, about sections, vocabulary, evidence registry).
- `lib/art.js` — ES-module copy of the generative art engine (canvas motifs,
  SVG diagrams).
- `lib/client.js` — DOM-level helpers shared by every page: manifest asset
  loader with `Image()` probe fallback, direction-aware wipes, zoom-through
  handoff (sessionStorage), cursor/grain/sound chrome, enter fade.
- `lib/decisions.js` + `lib/decisions-ui.js` (+ `lib/decisions-ui-shared.js`)
  — CSV parser/loader and the framework-agnostic explorer renderer.
- `components/TestBench.jsx` — client island on `/test/`: request runner over
  `/baseline.json`, output.csv field-by-field comparison, custom case scoring.
- `lib/live-api.js` + `components/LiveEnginePanel.jsx` — live engine client and
  panel (mirrors the static site's `assets/js/live-api.js` / `live-ui.js`):
  overrides, RUN LIVE, changed-field delta against the saved baseline.
- `public/baseline.json` — generated by `code/tools/gen_baseline.py`
  (double-run determinism verified) from the real engine.
- `public/assets/js/workflow.js` — byte-identical copy of the static site's
  workflow engine; the `/workflow/` page mounts it (canvas is imperative,
  loading it as a script keeps the engine identical in both frontends).
- `components/Chrome.jsx` — header with active-page states and wipe navigations.
- `components/Boot.jsx` — per-page chrome behaviors (guarded against duplicates).
- `components/WorkDetail.jsx` — the carousel/evidence/diagram work page.
- `components/DecisionExplorer.jsx` — client island on `/results/`.

`components/ThemeToggle.jsx` manages the persisted theme preference.
`components/AccountNav.jsx`, `lib/session.js`, and `app/account/page.jsx` connect
the account interface to the backend. Only authenticated API runs are recorded
in account activity; viewing saved baseline results does not create a run.
