# Kairos — Static Frontend

The earlier framework-free interface for the open-source Kairos financial
decision engine. It includes static results, evidence galleries, a workflow
visualizer, and a test bench connected to the Flask API.

The primary **React + Next.js app** lives in `../frontend-next/`. It includes
the current homepage and About design, theme controls, and user accounts.
See the [project README](../README.md) for setup and contribution instructions.

## Run

```bash
python3 -m http.server 8472 --directory frontend   # or any static server
# open http://127.0.0.1:8472/index.html
```

Every page is plain HTML — no build step. Assets are versioned (`?v=11`) for
cache busting: bump the token in the page `?v=` attributes when you change a JS
or CSS file, or browsers will serve the cached copy.

## Keeping both frontends in sync

This site and the React/Next.js port in `../frontend-next/` share the same
stylesheet, artwork, data files and logic. **After editing a shared file here,
mirror the change and run the parity guard:**

```bash
python3 code/tools/check_parity.py       # exits non-zero on drift
```

It checks byte-identical assets (CSS, `manifest.json`, `output.csv`,
`baseline.json`, the image set) and, for the mirrored modules (`art.js`,
`data.js`, `evidence.js`, the decision-explorer renderer), both the normalised
body and the exported surface — folding away only the sanctioned differences
(the module wrapper, comments, line endings, `assets/` vs `/assets/` paths).
Anything new that differs is reported as drift; see `code/README.md` for the
full manifest and `code/tests/test_parity.py` for how each tier is proven to
fail.

## Live engine (test-bench backend)

The Test Bench can execute **modified** requests through the real Python
pipeline, not just the precomputed baseline:

```bash
python3 code/serve_api.py      # http://127.0.0.1:8000 (loopback only)
```

The panel probes `/api/health`, prefills the dataset values, and RUN LIVE posts
the overrides to `/api/decide`; the answer is shown with a field-level delta
against the saved baseline. Without the server the panel says so and stays
inert — the baseline bench above keeps working. Point the page at another host
with `?api=http://host:port` or `window.KAIROS_API`.

## Interactions & effects

- Loader (letter reveal + %), film grain, crosshair cursor with x/y readout.
- Constellation words light near the cursor; strip drags with inertia,
  rubber-band edges, focus states and the `01 / STAGE 07` counter.
- Trace pen: a lamp-head light follows the tip while you draw — **draw downward**
  and the light is pulled down, stretches toward the floor and carries across to
  the About page, where the pendant drops in from the ceiling and swings into
  place (`bow-lamp` sessionStorage handoff, `lampDrop` / `coneRise`); zig-zag
  near a card = its stage page (zoom-through).
- Drag a **stage card downward** and its artwork is lifted out of the strip
  with the same lamp-head light riding along; releasing hands it to that stage
  page (`bow-zoom` handoff), where the artwork expands in place — the horizontal
  strip drag is cancelled for the pull.
- Direction-aware wipe veils between pages; per-card zoom-through when
  opening a stage from the strip (canvas/image ghost expands to full screen).
- Lamp pages: the pendant hangs **behind the section** as the backdrop light
  (swinging chain, flickering cone, breathing floor pool) while a **cursor
  torch** — a masked darkness layer with the hole rewritten inline on every
  pointer move — is what actually lights the type; the copy and the giant word
  are hidden in the dark until the torch passes over them. Section changes keep
  the blackout flash, the lamp swing and the quick nav. On touch devices
  (`pointer: coarse`) the darkness is dropped so the page stays readable.
- Stage pages: 5+-slide carousel (keyboard + arrows), next-slide preview pane,
  progressive story labels, evidence lightbox.
- Workflow page: PREV/NEXT + stage dots, TOUR (auto-advance) and FREE RUN
  modes, keyboard arrows, legend.
- Decision explorer: filter chips (status × method), request-id search,
  decision cards, detail lightbox with the payment plan table and the
  verbatim explanation from output.csv.
- Test bench: request picker with datalist + RANDOM, output.csv comparison
  badges (MATCH/DIFFERS per field), custom case builder with PASS/FAIL checks.
- Live engine panel: health pill (ONLINE/OFFLINE with the exact start command),
  dataset prefill on pick, amount field with ×0.5 / ×2 / ×5, request-date picker,
  partial-payment toggle, RUN LIVE, and a changed-fields delta
  (`affordable_now → not_affordable`) with the baseline explanation alongside.
- Shareable views: the URL records what you are looking at and restores it on
  load — explorer (`?status=&method=&q=&d=request_XX`), test bench
  (`?id=&cmp=0`) and live runs (`?lv=1&id=&amt=&date=&partial=0`).
- Branding: KAIROS favicon + icon set on every page, plus OG/Twitter preview
  tags (og:image 1200×630). The tag origin is the placeholder
  `kairos-buy-or-wait.example.com` — replace it with the real deploy URL.
- Sound toggle with EQ bars driving a generated ambience hum.
